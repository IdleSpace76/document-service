# document-service <br/>

Тестовое задание для ITQ.<br/>
Делал по YAGNI.<br/>
Текст задания лежит в docs.<br/>
В ***EXPLAIN.MD*** лежит пример поискового запроса.

## Требования
- Docker + Docker Compose
- JDK 21
- Maven 3.6.3+
- Свободный порт 5433 (меняется через конфиг приложения + .env)

## Как запустить сервис

1. Поднять PostgreSQL через Docker Compose:<br>```docker compose up -d```<br>
Контейнер itq-postgres должен подняться и слушать порт 5433.
2. Собрать проект:<br>```mvn clean install```<br>
3. Запустить Spring Boot-сервис:<br>```java -jar target/document-service-0.0.1-SNAPSHOT.jar```<br>

Чтобы удалить контейнер с данными:<br>```docker compose down -v```<br>

## Как запустить генератор

Утилита генерации документов работает только из-под запущенного приложения.<br>
Запускается она с помощью плагина из корня проекта: <br>```mvn -DskipTests exec:java```<br>
Конфигурационный файл генератора лежит в директории ```generator/generator.properties```.<br>
Свойства (значения в утилите по умолчанию (при отсутствии конфига!)):
```
count (10)                      - количество документов на генерацию
baseUrl (http://localhost:8080) - адрес активного приложения
author (generator)              - автор документов
```

## Логирование
Структура логирования:
```
logs/
  application.log     – общий лог сервиса
  workers.log         – лог фоновых воркеров (submit/approve)
```

```

```
***Паттерн Transactional Outbox*** : Реализовал бы реестр "догоняющим" - в основном сервисе outbox-таблица, воркер 
реестра читает статусы записей, достает новые и подгоняет данные в свою БД со сменой в главной бд статуса посредством запроса.<br>
Если никак не получается реализовать запись в реестре, то по ***паттерну Сага*** реализовал бы компенсацию в исходном сервисе
(но без частичной корректировки бизнес требований такое не реализовать).
